# Architecture and boundaries

Browser → same-origin Next.js proxy → FastAPI → restricted PostgreSQL role. Celery workers share the same domain services. PostgreSQL jobs/outbox persist requests before Redis dispatch. Object keys are scoped by organization/facility/world and content SHA256; authenticated downloads recheck RLS and content hashes. The storage adapter supports S3/MinIO and private Azure Blob Storage. Azure additionally restricts enumeration and physical keys to the configured GreenOps prefix. API readiness checks the actual migration revision, non-superuser/non-bypass runtime role, Redis and actual object storage.

There are 72 concrete SQLAlchemy tables. Identity is separate from world-bound records; composite foreign keys bind organization, facility, world and selected parents. Operational CRUD uses per-domain Pydantic contracts over typed shared ledger columns plus validated JSONB. Writes, ownership, zone grants, versions and evidence are checked in services and by separate PostgreSQL read/write policies. All scoped tables use FORCE RLS. Identity GUCs are transaction-local, so pooled connections cannot retain a previous user's scope. Opaque sessions are hashed; cookies are HttpOnly/SameSite and writes require CSRF plus an allowed Origin.

The migration role alone owns tables and bypasses RLS for bootstrap, migration and explicit restore. Its URL is absent from API/worker/scheduler environments. Narrow security-definer functions authenticate sessions and dispatch IDs/owners; they do not expose operational data to agent SQL. The agent has no SQL, arbitrary HTTP, filesystem or shell tool. Public fixture checksums are verified before loading trusted joblib models. Arbitrary artifact uploads are prohibited.

The configured cloud environment uses Supabase PostgreSQL 17 through a restricted transaction-pooler role; migrations use the separate session-pooler connection. Prepared statements are disabled for transaction pooling. Migration 0006 supplies read-only runtime policies for the static migration-version and metric catalogs; tenant policies remain scoped. The cloud statement timeout is 10 seconds, while the reproducible local default remains 3 seconds. These budgets are configurable and do not establish a cloud performance result.

Demo role buttons call the server-side authentication service using allowlisted accounts. The browser receives role names and emails, never passwords or provider/storage keys. Production mode disables this endpoint. Signing out clears the cached scope and operating data before another account is selected.

`research/starter` preserves original observations, private labels and injection configuration for isolated offline evaluation. `data/public/starter` is an explicit checksum-linked allowlist; facility configurations remove hidden injected events. The API image copies only public fixtures. Extended-world injection truth is ephemeral during generation and never written to runtime ledgers, documents or storage. Offline campaign truth is written only beneath `research/evaluation`.

Imported worlds contain exactly 17,280 base and 8,640 stress source rows. Water nulls remain null, energy quality is independent, and 17 invalid stress fill metrics are quarantined without dropping valid source rows. Canonical world/zone/time uniqueness rejects conflicting uploads across dataset versions. The independent extended world adds 25,920 zone-hours and identifiable category ledgers, telemetry, reserves, environment, parking and incident records. Category waste is an explicitly separate stream, not a reconstruction of imported aggregate waste.

Hourly readings describe intervals ending at their timestamp. Consumption sums disjoint zones; states use declared last/sample-mean aggregation. Coverage includes expected zone-hour intervals, missing samples and null readings. Occupied bed-days exclude non-inpatient zones; OPD activity remains separate. Cost/carbon use named, versioned illustrative factors; a period crossing a factor change is unavailable until segmented.

The virtual clock controls event cutoffs, ages and demo risks. System time controls sessions, audits, leases and scheduling. Agent runs freeze domain snapshots, documents, clock/config versions and engineering baselines before executing. Reads stay pinned; mutations recheck current grants, policy, owner and optimistic versions. Each tool call, matching response, usage record and ordered SSE event is persisted. Aggregate tool facts link to the scoped persisted tool result; owner identities are not evidence records. Waste category totals aggregate all positive scoped movement balances independently of bounded batch detail. HTTP success responses are sent after transaction commit; SSE polling opens separate short transactions. Cancellation is checked before every tool; retries use server idempotency keys. A run lease prevents concurrent execution. Provider errors become visible states and bounded deferred retries.

Nineteen typed tools span every operational domain. Tools calculate numeric results and save simulations/proposals/actions using the same services as HTTP. Number/rounding/citation checks withhold unsupported answers; this guard is conservative, not proof of every natural-language assertion. Final answer text is released after grounding, while tool progress streams through SSE. Provider chunks and parallel tool calls are supported; mutations execute sequentially under authorization and transactional checks. No hidden reasoning is persisted.

The simulation engine advances 15-minute steps over 1–72 hours. It protects fire storage, prioritizes essential power before pump/nonessential loads, tracks water/energy/fuel/parking balances and explicit unmet demand, and combines waste age/fill deadlines. Low/central/high demand sensitivity is not a probability interval. Saved scenarios compare only identical frozen baselines and horizons.
